## Карта исполнения baseline

`Frontend → POST generate-plan → Celery generate_meal_plan → _generate_by_mode → [agent_cli_runtime | tasks._generate] → generate_day_plan → [tool loop | _run_pipeline] → finalization → normalized rows/cache → GET plan`.

Отдельно: `demo endpoints → demo_pipeline` и `catalog endpoints → catalog/source Celery tasks → catalog_agent_runtime → admission`. Dynamic registration FastAPI/Celery и CLI — настоящие consumers даже без прямого callsite.

## Дублирование: не список удаления

Дублируются week orchestration, compatibility, progress/state construction, result finalization и validation/repair boundaries. Общие helpers canonical_pipeline/relational_store/retriever/calculator используются несколькими paths. Удаление целого модуля по одному unused symbol недопустимо. `_run_pipeline` reachable при flag OFF. Demo reachable из routes. Catalog ingest legacy helper и ingredient calorie validator имеют test callers: дальнейшая судьба требует сохранения нужного контракта, не удаления tests ради green suite.
