# Mealy

Mealy — персональный AI-помощник для питания, планирования рациона, списка покупок и здоровых бытовых сценариев.

Приложение собирает анкету пользователя, подбирает блюда из проверенного каталога, считает КБЖУ, валидирует итоговый план и отдаёт понятный недельный сценарий: что есть, когда готовить, что купить и как перенести план в календарь.

> Mealy не позиционируется как врач или медицинская консультация. Это бытовой помощник для питания и планирования, который помогает пользователю принимать более организованные решения.

---

## Позиционирование

**Одной строкой:**  
Mealy превращает цель пользователя в проверенный план питания с рецептами, календарём и списком покупок.

**Короткий питч:**  
Обычные AI-чаты умеют красиво писать про еду, но часто ошибаются в калориях, граммовках и ограничениях. Mealy строит рацион только из проверенного каталога блюд, пересчитывает нутриенты детерминированными инструментами и показывает результат как удобное приложение, а не как простыню текста.

**Что мы продаём пользователю:**

- меньше хаоса вокруг еды на неделю;
- меньше ручного подсчёта КБЖУ;
- меньше забытых продуктов в магазине;
- больше доверия к AI-плану, потому что цифры проверяются кодом;
- один ежедневный экран вместо набора таблиц, заметок и промптов.

**Не позиционируемся как:**

- медицинский диагнозатор;
- “ещё одна обёртка над ChatGPT”;
- трекер, куда пользователь вручную заносит каждую ложку;
- сервис доставки готовой еды.

**Позиционируемся как:**

- AI meal planner;
- персональный помощник по питанию;
- бытовой wellness-инструмент;
- bridge между рационом, календарём и покупками.

## Окраска и стиль

Для Mealy лучше использовать **спокойный premium consumer health стиль**, ближе к Apple Health / Apple Fitness / современному grocery planner, а не типичный “зелёный ЗОЖ”.

### Основная идея

Интерфейс должен ощущаться:

- чистым;
- доверительным;
- ежедневным;
- не медицински пугающим;
- не детским;
- не “эко-лавкой” в бежево-зелёных тонах.

Питание — эмоциональная и бытовая тема. Пользователь должен чувствовать не “меня лечат”, а “мне спокойно собрали понятный план”.

### Рекомендуемая палитра

| Роль | Цвет | Зачем |
|------|------|-------|
| Основной фон | `#ffffff` | Чистота, простота, читаемость |
| Вторичный фон | `#f5f5f7` | Мягкие секции и панели |
| Основной текст | `#1d1d1f` | Apple-like нейтральный ink |
| Вторичный текст | `#6e6e73` | Подписи, пояснения, метаданные |
| Главный action-color | `#0066cc` | Кнопки, ссылки, активные состояния |
| Action hover/focus | `#0071e3` | Фокус и интерактивность |
| Action на тёмном | `#2997ff` | Ссылки и CTA на чёрных панелях |
| Тёмная поверхность | `#000000` / `#272729` | Hero, summary, важные продуктовые блоки |
| Border / hairline | `#e0e0e0` | Тонкие границы без тяжёлых теней |
| Success | `#16833a` | Только для “ok”, “within target”, “balanced” |
| Warning | `#b42318` | Только для ограничений, ошибок, дисклеймеров |

### Почему не зелёный как основной

Зелёный слишком быстро превращает продукт в generic health app. Он подходит для статусов, меток “balanced” и мягких подтверждений, но не должен быть главным брендовым цветом.

Главный цвет лучше сделать синим:

- он ассоциируется с действием и доверием;
- хорошо работает в iOS/macOS-паттернах;
- не спорит с фотографиями еды;
- не делает интерфейс “диетологическим плакатом”.

### Визуальный язык

Использовать:

- крупную типографику;
- много воздуха;
- плоские поверхности;
- чёрные hero/summary-блоки;
- один заметный action-color;
- реальные фото еды или очень аккуратные продуктовые карточки;
- нижнюю навигацию на mobile и левый navigation rail на desktop;
- понятные экспорты: Calendar, PDF, copy, share.

Не использовать:

- декоративные градиенты;
- “здоровые” зелёно-бежевые палитры как основу;
- heavy shadows;
- glassmorphism ради glassmorphism;
- emoji как главный UI-язык;
- агрессивные медицинские красные/синие панели;
- маркетинговые hero-секции вместо полезного первого экрана.

### Тон текста

Тон продукта: спокойный, уверенный, бытовой.

Писать так:

- “План на неделю готов”
- “Добавить в календарь”
- “Список покупок”
- “Проверено по целевым калориям”
- “AI guidance is informational only”

Не писать так:

- “Ваш идеальный рацион от искусственного интеллекта”
- “Лечим питание”
- “Революция диетологии”
- “100% правильный план”

## Как работает продуктовый сценарий

1. Пользователь проходит короткую анкету.
2. Система рассчитывает целевую калорийность.
3. Retriever выбирает подходящие рецепты из каталога.
4. Agent собирает план питания.
5. Validator проверяет КБЖУ и ограничения.
6. Если план не проходит проверку, пайплайн исправляет его.
7. Пользователь получает Today dashboard, план по дням, рецепты, список покупок и экспорты.

```
Анкета
  -> профиль и ограничения
  -> подбор рецептов
  -> генерация плана
  -> проверка КБЖУ
  -> сохранение
  -> Today / Week / Shopping / Export
```

### Два режима генерации

| Режим | Для чего | Что нужно |
|-------|----------|-----------|
| Demo pipeline | Надёжный локальный показ без LLM | Backend + DB + Redis |
| Agent / LLM pipeline | Реальная AI-генерация | Backend + Celery + OpenRouter key |

Demo pipeline важен для презентации: он показывает весь продуктовый UX без зависимости от внешней LLM.

## Быстрый старт

### Требования

- Python 3.11+
- Docker + Docker Compose
- `uv`
- Node.js + npm

### Backend

```bash
docker compose up -d db redis

cd backend
uv sync --dev
uv run alembic upgrade head
uv run python scripts/seed_recipes.py
uv run python scripts/seed_demo_user.py
uv run uvicorn app.main:app --reload --port 8000
```

Swagger:

```text
http://localhost:8000/docs
```

### Frontend

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

Frontend:

```text
http://127.0.0.1:4321
```

### Demo-режим

Для стабильного локального показа во `frontend/.env`:

```bash
PUBLIC_API_BASE_URL=http://localhost:8000
PUBLIC_USE_DEMO_PIPELINE=true
```

В этом режиме frontend использует demo endpoints и не требует OpenRouter.

### Реальный LLM-режим

Во `frontend/.env`:

```bash
PUBLIC_USE_DEMO_PIPELINE=false
```

В backend `.env` должен быть настроен ключ LLM-провайдера. Затем отдельно запустить worker:

```bash
cd backend
uv run celery -A app.worker worker -l info
```

## Валидация и доверие

Главная техническая идея Mealy: AI не должен просто “написать рацион”.

Пайплайн работает так:

1. AI получает ограниченный контекст.
2. Блюда берутся из каталога.
3. Ответ должен быть структурированным.
4. КБЖУ проверяется кодом.
5. Ошибки возвращаются в цикл исправления.
6. Пользователь видит только безопасную диагностику, без сырых промптов и provider payloads.

Это делает продукт ближе к контролируемой системе планирования, чем к обычному чат-боту.
